# 模型配置：本机实操陷阱

这些点会改错文件、把窗口钳回 `272000 × 95% ≈ 258400`，或让密钥/提供方无法工作。

## 改对文件

第三方模型经常写在 `~/.codex/<profile>.config.toml`，而不是默认 `config.toml`。

新增模型时从 [template.config.toml](template.config.toml) 生成新 profile，文件名和 `provider-id` 相同。未指定 id 时用模型系列名：`grok-4.6` → `grok`，`gpt-5.6-sol` → `gpt`，`deepseek-v4-flash` → `deepseek`。

`provider-id` 必须全量替换。只改第一处会导致 `model_provider` 和 `[model_providers.<id>]` 对不上。

`model_catalog_json` 写进默认配置，会让所有会话替换内置目录。只改当前真正设置 `model = "<slug>"` 的那份 TOML。

未要求时不要把用户的默认模型改成新供应商。只有用户加了 `--as-default` 时，才备份并覆盖 `~/.codex/config.toml`。多 profile 用户应新增或编辑 profile。`base_url` 不能留空。

`adjust_context_window.py --profile <id>` 时，若 `~/.codex/<id>.config.toml` 还不存在，脚本会从模板新建（可同时传 `--base-url`）。不要对默认 `config.toml` 做这种自动创建。`base_url` 仍为空则 Codex 会 builder error，需要补上后再开会话。 `--from-cache` 而本机没有 `models_cache.json` 时，脚本会警告并按 CLI/模板默认值合成目录条目，不再中止。

`codex --profile` 不能搭配 `doctor`。校验自定义目录用：

```bash
codex -c model_catalog_json='"/home/<user>/.codex/yjwd-grok-models.json"' debug models > /tmp/codex-models-debug.json
```

把 JSON 重定向到文件再查。不要把 `codex debug models` 管道进 Python heredoc，heredoc 会吃掉 stdin。

## 不要猜比默认更大的窗口

用户没给上下文长度或思考档位时，先查官方文档。查不到就用模板 `skill.codex-model-config` 默认值（258400 + 五档思考，默认档 `medium`），或传 `--defaults`。不要编造 400k/1M 这类未证实的数。

本机 `models_cache.json` 只是克隆骨架。缓存里的窗口和档位不能证明官方上限，slug 仍必须和 TOML `model` 全等。

## PowerShell 跑脚本

`--reasoning-levels low,medium,high,xhigh` 在 PowerShell 里必须写成：

```powershell
python scripts\adjust_context_window.py --model grok-4.6 --profile yjwd-grok --bootstrap-bundled --from-cache --context-window 300000 --reasoning-levels "low,medium,high,xhigh" --yes
```

未加引号时，逗号会变成数组，argparse 可能只吃到 `low`，后面变成无法识别的参数。

`--bootstrap-bundled` 会从 Python 里启动 `codex`。PowerShell 的 `Get-Command codex` 经常是 `codex.ps1`，Python 启动不了（`[WinError 2] 系统找不到指定的文件`）。脚本会改找 PATH 上的 `codex.cmd` / `codex.exe`。若仍失败，先在同一终端执行 `Get-Command codex.cmd, codex.exe`。

## Windows 控制台编码（GBK）

中文 Windows 默认代码页常是 GBK。Python `subprocess.run(..., text=True)` 会按 locale 解码子进程输出。`codex debug models --bundled` 输出的是 UTF-8 JSON（含 U+2026 `…` 等），GBK 解到字节 `0xa6` 时会出现：

```
UnicodeDecodeError: 'gbk' codec can't decode byte 0xa6 ...
TypeError: the JSON object must be str, bytes or bytearray, not NoneType
```

`--dry-run` 不会调用 `codex`，所以看不出这个问题。本 skill 的脚本按字节捕获再按 UTF-8 解码；stderr 即使混有非 UTF-8 也不会把整次调用打崩。

不要自己写 `text=True` 去接 bundled JSON，也不要用 PowerShell `>` 保存 JSON（会变成 UTF-16）。请用：

```powershell
python scripts\adjust_context_window.py --model grok-4.6 --profile yjwd-grok --bootstrap-bundled --from-cache --context-window 300000 --reasoning-levels "low,medium,high,xhigh" --yes
```

脚本会把 `<profile>-models.json` 写进 `--codex-home`（默认 `~/.codex`），不会覆盖 `models.json`。若报 `Permission denied`，检查该目录可写，或显式传入可写的 `--codex-home`。若失败的是 `git` 写 `.git/index.lock`，那是 Codex 沙箱保护了 `.git/`，不是编码问题，见 [codex-sandbox-permissions.md](codex-sandbox-permissions.md)。


## 档位列表不在 TOML 里

`--reasoning-levels low,high,xhigh` 写进 `models.json` 的 `supported_reasoning_levels`，选择器才会少档。profile TOML 只有 `model_reasoning_effort`（当前用哪一档）。只改 TOML、不跑 `adjust_context_window.py`，UI 档位列表不会变。

## slug 必须全等

`model = "grok-4.6"` 对不上目录里的 `x-ai/grok-4.6`。从 `models_cache.json` 克隆时，把 `slug` 改成 TOML 里的值。

## 第三方模型用 Python 写文件、改文件没有摘要

这不是 `base_url` / `wire_api` 的问题，也不是窗口没抬上去。看专用 catalog 条目：

- `apply_patch_tool_type` 为 `null`：Codex 不把 `apply_patch` 发给该模型。模型只能用 Python/`cat`/heredoc 整文件重写，内容截断时就像写丢文件。CLI/IDE 的改文件摘要来自 `apply_patch` 结果，没有这个工具就不会出现 GPT 那种每轮文件总结。
- `shell_type` 为 `default` 或缺失：旧缓存常见空值。缺失时 Codex 可能直接拒绝启动；`default` 则走旧 shell，而不是 GPT 目录用的 `unified_exec`。

克隆 Grok / DeepSeek 缓存条目时这两个字段经常是空的。追加或修复时写成：

```json
"apply_patch_tool_type": "freeform",
"shell_type": "unified_exec"
```

`scripts/adjust_context_window.py` 在目标条目缺少这两项时会一并补上。打开工具只让 Codex 走同一条落地路径；不保证模型能按 GPT 的 patch 格式落地。改完后重载客户端并开新对话。Grok 的例外见下一节。

## Grok 先别开 apply_patch freeform

打开 `apply_patch_tool_type: "freeform"` 只让 Codex 把工具发给模型。Grok 4.6 会调用它，但当前接线常校验失败（`The first line of the patch must be '*** Begin Patch'`），随后仍用 Python / `exec_command` 写文件。失败轮次浪费 token；patch 没成功应用，就不会有 GPT 那种改文件摘要。

因此只动 Grok 这一条，不要整份 catalog 回滚：

- `apply_patch_tool_type`：保持 `null`（或改回 `null`），让它直接走 shell/Python，少绕路。
- `shell_type`：保持 `"unified_exec"`，不要改回 `default`。
- `web_search_tool_type`：保持 `"text"`。GPT 用 `"text_and_image"` 是另一套搜索回传，没有证据对 Grok 更省或更稳。

`adjust_context_window.py` 在字段为空时仍会填 `freeform`。配完 Grok 后若实测 patch 全失败，把该 slug 改回 `null`。等 Codex 对这家提供方的 freeform 修好再开。

## 不要把 DeepSeek 的 verbosity 抄给 Grok

`support_verbosity` / `default_verbosity` 只决定 Codex 会不会在 Responses 请求里带 `text.verbosity`（`low` / `medium` / `high`）。这不是「模型会不会说话」，也不等于上游真会控篇幅。

- OpenAI GPT-5 家族：官方参数。Codex 的 `model_verbosity` 示例也写明是 GPT-5 family、Responses API。
- DeepSeek：官方 Responses 兼容表写 `text.verbosity` **可传入但不生效**。安装器目录里的 `true` / `"low"` 只是协议兼容，不是控篇幅。
- Grok 4.6：官方模型页文档化的是 `reasoning_effort`（`low` / `medium` / `high` / `xhigh`）。REST Responses 的 `text` 示例只有 `{ "format": { "type": "text" } }`，没有 `verbosity`。目录保持 `support_verbosity: false`、`default_verbosity: null`。

把 Grok 改成 DeepSeek 那种 `true` / `"low"`，最多被上游忽略，还可能让 Codex 误发无效字段。要控 Grok 篇幅用 prompt 或思考档，不要开 verbosity。能力标志按各家官方文档单独设，不要跨供应商抄 catalog。

## 配了 catalog 后第三方模型调不了工具

自定义 catalog **整份替换**内置目录。若 `grok-4.6` 这类条目是从 `gpt-6-astra` 克隆来的，会带上 `tool_mode=code_mode_only` 和 `include_skills_usage_instructions=false`。Grok 看不到初始 shell/apply_patch/MCP/skills，而注释掉 `model_catalog_json` 后工具又恢复。

处理：重新跑 `adjust_context_window.py --profile <id> --bootstrap-bundled --from-cache`（不要 `--as-default`）。脚本会改克隆直连工具骨架，并去掉 `code_mode_only`。不要手写只有窗口字段的短条目。显式 `--clone-from gpt-6-astra` 才会保留 code mode。字段说明见 [model-catalog-json.md](model-catalog-json.md)。

## 没有专用 catalog 时

1. 用 `codex debug models --bundled` 生成本机完整目录，或脚本加 `--bootstrap-bundled`。这不是访问 OpenAI，也不需要代理。
2. 追加自定义模型，不要只留一条把 bundled 盖掉。
3. 未知 slug 会走 fallback：`272000 × 95% ≈ 258400`。

供应商一键脚本经常写入「只有该供应商模型」的目录。那会让 OpenAI 内置模型从选择器消失。

不要为了创建 catalog 去拉 `api.openai.com` 或探测 `localhost:7897` / `7890` / `10808`。目录来源见 [catalog-source.md](catalog-source.md)。代理只在实际上游请求失败、且本机已有客户端时才考虑，用环境变量，不要写进 TOML。

## 密钥与提供方

- 用 `env_key`，密钥写到 `~/.config/models.env`（没有则创建，有则追加）。不要把 API Key 写成 `experimental_bearer_token`，也不要回显密钥。
- 提供方 id 不要用保留名：`openai`、`ollama`、`lmstudio`。
- `[model_providers.<id>]` 只能写在用户级配置，不能写在项目 `.codex/config.toml`。
- `env_key`、`wire_api`、`base_url` 必须在提供方段内，不能单独挪到文件顶部。
- 不要把 `model_catalog_json` 指到 `~/.codex/models.json`（Codex 保留文件，缺 `shell_type` 会无法启动）。用绝对路径的 `<profile>-models.json`。

## 不要擅自跑安装器

`bash <(curl ...)` 或 PowerShell `irm | iex` 会改默认 `config.toml`，并可能删除冲突字段。只有用户明确要求时才运行，跑之前先说明它会动哪些文件。

## 客户端

CLI / ChatGPT 桌面端 / VS Code 插件共用用户配置，但都只在启动时加载。Reload Window 或重启后再开新对话。

会话按认证方式分组。切换提供方后另一组历史被隐藏，不是删除。

## 脚本

新建 profile：

```bash
python3 scripts/init_profile.py --model grok-4.6 --base-url https://example.invalid/v1 --yes
```

模型已在默认配置和 `models.json` 里：

```bash
python3 scripts/adjust_context_window.py \
  --model deepseek-v4-flash-vision-exp \
  --context-window 400000 \
  --yes
```

模型在 profile 里，且 catalog 还没有这条：

```bash
python3 scripts/adjust_context_window.py \
  --model grok-4.6 \
  --context-window 500000 \
  --profile yjwd-grok \
  --bootstrap-bundled \
  --from-cache \
  --yes
```

脚本发现默认 `config.toml` 的 `model=` 对不上时会拒绝写入，避免把 `model_catalog_json` 写进正在用的另一个供应商配置。提供方段落仍需按 [workflow.md](workflow.md) 核对。若条目的 `apply_patch_tool_type` 为空或 `shell_type` 为 `default`，脚本会改成 `freeform` / `unified_exec`。
