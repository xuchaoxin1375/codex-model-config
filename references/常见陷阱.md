# 模型配置：本机实操陷阱

这些点会改错文件、把窗口钳回 `272000 × 95% ≈ 258400`，或让密钥/提供方无法工作。

## 改对文件

第三方模型经常写在 `~/.codex/<profile>.config.toml`，而不是默认 `config.toml`。

新增模型时从 [template.config.toml](template.config.toml) 生成新 profile，文件名和 `provider-id` 相同。未指定 id 时用模型系列名：`grok-4.6` → `grok`，`gpt-5.6-sol` → `gpt`，`deepseek-v4-flash` → `deepseek`。

`provider-id` 必须全量替换。只改第一处会导致 `model_provider` 和 `[model_providers.<id>]` 对不上。

`model_catalog_json` 写进默认配置，会让所有会话替换内置目录。只改当前真正设置 `model = "<slug>"` 的那份 TOML。

未要求时不要把用户的默认模型改成新供应商。多 profile 用户应新增或编辑 profile。`base_url` 不能留空。

`codex --profile` 不能搭配 `doctor`。校验自定义目录用：

```bash
codex -c model_catalog_json='"/home/<user>/.codex/models.json"' debug models > /tmp/codex-models-debug.json
```

把 JSON 重定向到文件再查。不要把 `codex debug models` 管道进 Python heredoc，heredoc 会吃掉 stdin。

## slug 必须全等

`model = "grok-4.6"` 对不上目录里的 `x-ai/grok-4.6`。从 `models_cache.json` 克隆时，把 `slug` 改成 TOML 里的值。

## 没有 models.json 时

1. 用 `codex debug models --bundled` 生成本机完整目录，或脚本加 `--bootstrap-bundled`。这不是访问 OpenAI，也不需要代理。
2. 追加自定义模型，不要只留一条把 bundled 盖掉。
3. 未知 slug 会走 fallback：`272000 × 95% ≈ 258400`。

供应商一键脚本经常写入「只有该供应商模型」的目录。那会让 OpenAI 内置模型从选择器消失。

不要为了创建 catalog 去拉 `api.openai.com` 或探测 `localhost:7897` / `7890` / `10808`。目录来源见 [catalog-source.md](catalog-source.md)。代理只在实际上游请求失败、且本机已有客户端时才考虑，用环境变量，不要写进 TOML。

## 密钥与提供方

- 用 `env_key`，密钥写到 `~/.config/models.env`（没有则创建，有则追加）。不要把 API Key 写成 `experimental_bearer_token`，也不要回显密钥。
- 提供方 id 不要用保留名：`openai`、`ollama`、`lmstudio`。
- `[model_providers.<id>]` 只能写在用户级配置，不能写在项目 `.codex/config.toml`。
- `env_key`、`wire_api`、`base_url` 必须在提供方段内，不能单独挪到文件顶部。
- DeepSeek 文档里的 `model_catalog_json = "~/.codex/models.json"` 不可靠，改绝对路径。

## 不要擅自跑安装器

`bash <(curl ...)` 或 PowerShell `irm | iex` 会改默认 `config.toml`，并可能删除冲突字段。只有用户明确要求时才运行，跑之前先说明它会动哪些文件。

## 客户端

CLI / ChatGPT 桌面端 / VS Code 插件共用用户配置，但都只在启动时加载。Reload Window 或重启后再开新对话。

会话按认证方式分组。切换提供方后另一组历史被隐藏，不是删除。

## 脚本

新建 profile：

```bash
python3 scripts/init_profile.py --model grok-4.6 --base-url https://example.invalid/v1 --yes
```

模型已在默认配置和 `models.json` 里：

```bash
python3 scripts/adjust_context_window.py \
  --model deepseek-v4-flash-vision-exp \
  --context-window 400000 \
  --yes
```

模型在 profile 里，且 catalog 还没有这条：

```bash
python3 scripts/adjust_context_window.py \
  --model grok-4.6 \
  --context-window 500000 \
  --profile yjwd-grok \
  --bootstrap-bundled \
  --from-cache \
  --yes
```

脚本发现默认 `config.toml` 的 `model=` 对不上时会拒绝写入，避免把 `model_catalog_json` 写进正在用的另一个供应商配置。提供方段落仍需按 [workflow.md](workflow.md) 核对。
